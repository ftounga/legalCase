## SF-289-02 — Actions inline (répondre à une question IA, marquer une pièce obtenue)
**Objectif** : permettre, depuis le bloc « ce qui requiert ton attention », de **répondre à une question de l'app** et de **marquer une pièce manquante comme obtenue** sans quitter la Vue d'ensemble.
**Nominal** : un item `QUESTION_IA` expose un champ réponse inline (`POST /ai-questions/{id}/answer`) ; un item `PIECE_MANQUANTE` expose un bouton « Marquer obtenue » (`PUT /pieces-manquantes/status`, statut OBTENUE). Après succès → l'item disparaît du bloc, la vue se rafraîchit.
**Erreurs** : échec API → snackbar non bloquant, item conservé ; réponse vide → bouton désactivé.
**Critères** : action inline opérationnelle (endpoints existants) ; complétion (item retiré) ; isolation workspace (endpoints déjà isolés) ; les arbitrages complexes (risques) **restent routés** (pas inline).
**Tests (Jest)** : champ réponse → POST ; marquer obtenue → PUT ; refresh post-succès ; erreur non bloquante.
**Hors scope** : arbitrage des risques inline, édition multi-questions en masse.
**Impact** : frontend uniquement (endpoints existants). Aucun backend, aucune migration.

## SF-289-03 — Documents versés pendant une phase
**Objectif** : sur un événement de **phase** du fil, déplier les **pièces versées pendant la fenêtre de cette phase** (`[enteredAt(phase), enteredAt(phase suivante)[`, ou jusqu'à aujourd'hui pour la phase courante).
**Nominal** : `OverviewService` attache aux `TimelineEvent` de voie `PROCEDURE` les documents `created_at ∈ fenêtre` (via `DocumentRepository`) ; le frontend les rend dans l'**accordéon de pièces existant** (champ `attachments` déjà au contrat).
**Erreurs** : aucune pièce dans la fenêtre → pas d'accordéon (dégradation) ; fail-open conservé.
**Critères** : fenêtre calculée correctement (tri des phases par `enteredAt`) ; phase courante = fenêtre ouverte jusqu'à maintenant ; aucune nouvelle table ; lecture seule.
**Tests** : `OverviewServiceTest` — pièces correctement réparties par fenêtre de phase ; fail-open inchangé.
**Hors scope** : reclassement de pièces, pièces hors phases.
**Impact** : backend (OverviewService) + rendu frontend déjà compatible (attachments). Aucune migration.

## SF-289-04 — Export PDF du journal du dossier
**Objectif** : bouton « Exporter le journal (PDF) » qui génère un PDF lisible du fil (état + attention + chronologie).
**Nominal** : génération **frontend** via la lib PDF déjà présente dans le projet (pdfmake) à partir des données `/overview` déjà chargées ; titre = dossier, sections Pilotage / Attention / Fil (passé + futur), dates en mono. Design sobre (navy/or).
**Erreurs** : si overview non chargé → bouton désactivé.
**Critères** : PDF généré sans appel backend ; contenu fidèle à la vue ; nommage `journal-{dossier}.pdf`.
**Tests (Jest)** : clic → appel du générateur PDF (mické) avec les sections attendues.
**Hors scope** : export backend, mise en page avancée, export ZIP (existe déjà).
**Impact** : frontend uniquement. Aucun backend, aucune migration.

## SF-289-05 — Panneau d'aperçu latéral des pièces (drawer)
**Objectif** : remplacer l'ouverture d'un onglet navigateur (V1) par un **drawer** latéral qui prévisualise la pièce **dans la vue**, sans perte de contexte.
**Nominal** : clic `[aperçu]` sur une pièce → `mat-sidenav`/drawer s'ouvre à droite avec le rendu `/content` (ou `/preview`) ; bouton « ouvrir dans un onglet » + « télécharger » conservés ; fermeture = retour au fil.
**Erreurs** : pièce supprimée/404 → message dans le drawer (pas d'onglet blanc).
**Critères** : aperçu dans le drawer (pas de navigation) ; isolation (endpoints existants) ; fermeture propre ; fallback download conservé.
**Tests (Jest)** : clic aperçu → drawer ouvert + bonne URL ; 404 → message ; fermeture.
**Hors scope** : annotation de pièce, multi-aperçu.
**Impact** : frontend uniquement.

## SF-289-06 — Stepper masqué sur la Vue d'ensemble
**Objectif** : le stepper sticky n'apparaît **pas** quand l'onglet Vue d'ensemble est actif (le bandeau pilotage tient le rôle) ; **inchangé** sur les autres onglets. (Décision PO 2026-06-13 : absorption douce.)
**Nominal** : `case-file-detail` masque `app-case-dashboard-stepper` quand `selectedTabIndex === TAB_OVERVIEW (0)`.
**Erreurs** : n/a.
**Critères** : stepper absent sur Vue d'ensemble, présent sur Dossier/Analyse/Décision/Suivi ; réversible (1 condition `[hidden]`/`@if`) ; **smoke E2E navigation** (préoccupation transversale navigation).
**Tests (Jest)** : `case-file-detail` — stepper masqué si onglet 0, visible sinon.
**Hors scope** : suppression totale du stepper, mini-barre de remplacement (options B/C écartées par le PO).
**Impact** : frontend (`case-file-detail`). **Préoccupation transversale navigation** → smoke E2E nav avant push. Aucune migration.
